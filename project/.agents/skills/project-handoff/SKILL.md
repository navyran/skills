# 项目任务交接

把当前任务保存为接手 Agent 无需原会话也能理解的交接文档。适用于任意项目，不依赖特定 IDE、MCP、记忆服务、编程语言或部署平台。

## 确定交接范围

- 用户指定任务时仅交接该任务；否则交接当前会话正在执行的目标及其尚未闭合的子任务。只有多个独立目标无法区分时才询问。
- 区分“生成交接资料”和“实际派发执行”。本技能默认完成资料落盘与接手提示词；只有用户明确要求创建会话、派发给指定 Agent 或发送消息时，才使用宿主相应工具。没有派发能力时提供可复制提示词，不声称已转交。
- 先读目标项目适用的 AGENTS.md 等规则。业务限制、授权范围和必须遵守的门禁随任务交接，不把当前项目的固定规则写成本技能的通用规则。

## 收集最小充分上下文

只读取与所交接任务相关的会话、文件和状态。优先使用当前上下文；缺失历史时可用宿主提供的会话读取工具或用户指定记录，不扫描其他会话的私有日志来补齐。

### 目标、提示词与决策

- 记录业务目标、交付物、验收标准、背景、已确定方案、关键取舍及明确排除项。
- 保存最近一次实质任务的用户提示词原文，以及此后改变范围或执行方式的补充原文。若最新消息仅为“交接给其他 Agent”，另列为交接指令，不能用它替代业务提示词。
- 需要最后一轮会话时，补充最后一次 Agent 回复及最后操作结果，注明各自角色与来源；不要导出整段无关聊天。
- 原文不可获取时明确写“原文不可获取，以下为摘要”，标记来源和缺口。记忆摘要、工具返回或旧报告不能冒充用户原话、当前授权或当前执行事实。
- 摘要说明任务为何停在这里。保留影响续接的失败尝试及结论，避免接手者重走已证伪路线。

### 项目、文件与分支

- 记录项目名、工作目录、代码仓库或资料位置、相关子项目；多仓库分别列出。
- 对 Git 项目只读核验根目录、当前 worktree、分支或 detached HEAD、完整 HEAD SHA、upstream，以及已暂存、未暂存、未跟踪的相关文件。可用 `git status --short --branch`、`git rev-parse HEAD`、`git diff --stat`、`git diff --cached --stat`，再定向查看必要差异。
- 分开记录工作分支、计划合入分支、实际部署版本；不能把本地 HEAD 当成已推送或已部署。远端状态若只来自本地缓存，注明未实时核验，不为生成交接自动 fetch、pull、切分支或提交。
- 按文件说明用途、关键入口和改动状态；标记与本任务无关或归属不明的改动，不把工作区全部改动归为本任务成果。引用行号须实际核验。
- 跨机器以仓库相对路径和 SHA 定位，并补充本机绝对路径。未提交改动、未跟踪文件及仅本机文档不能靠分支恢复，必须列出可用性与缺失的搬运步骤。
- 需要搬运时，仅为任务相关且已检查脱敏的文件生成附件或补丁，分别说明暂存与未暂存部分；不默认执行 stash、commit、push 或打包整个目录。无 Git 项目写“不适用”，改记文档版本和资料位置。

### 进展、证据与恢复点

- 每个未闭合子任务列出状态、已做事项、剩余动作、依赖或阻塞、下一步及完成判据。状态采用“待开始／进行中／阻塞／完成”；完成必须有可定位证据。
- 验证结果记录命令或操作、目标环境、版本、结果及证据位置；区分已通过、失败、跳过和未执行。生成交接不需要重跑全部验证；旧结果标明原验证时点。
- 检查已有计划、TODO、实施记录、测试报告或发布记录，列明用途、权威性、是否存在与是否随仓库共享。过期记录注明差异，不用历史结论覆盖当前状态。
- 有正在运行的长任务时，记录外部任务 ID、状态查询入口、最近检查点、产物和恢复办法；指出仅本会话有效的进程或会话 ID。接手前先查询已有任务，不盲目重复提交、重复计费或重启。
- 只记录凭据的受控获取位置和用途，脱敏提示词、链接、命令及附件中的密码、Token、Cookie、签名等敏感值。

## 保存交接文档

按 [交接模板](references/handoff-template.md) 填写，删除不适用的条件项，缺失信息写“未知／未核验”，不要留下空占位符。

1. 优先使用用户指定路径或项目已有交接目录；没有约定时保存到项目根目录 `handoffs/<任务短名>-<YYYYMMDD-HHmmss>/HANDOFF.md`。时间使用用户时区并注明偏移。同名已存在时使用新后缀，不覆盖其他交接。
2. 项目只读或无目录时使用用户可访问的工作区；无法写文件则直接输出完整文档并说明未落盘。
3. 已有进度文档只引用，不另建重复 TODO 作为第二套状态源。没有进度文档时，HANDOFF.md 的进展表就是本次保存的恢复点，不另造计划文档。
4. 文档末尾填好可直接发送给接手 Agent 的提示词，包含目标、交接文件位置、首要阅读材料、下一步和边界。跨机器若无法读本机路径，明确需要一并提供的文档或附件，并将关键上下文写入提示词。
5. 若用户指定多个接手者，明确各自负责的子任务与共享文件的修改边界；未指定时不自行启动多个 Agent。

## 生成后告诉用户如何在另一个 Agent 中使用

交接文档生成后，最终回复必须直接给出以下使用步骤，不能只提供文件链接或让用户自行查找提示词：

1. 在另一个 Agent 中打开目标项目或工作目录，使用本次实际项目路径说明。同一机器可直接读取交接文件；不同机器需先准备对应仓库版本，再提供交接文档及必要附件，按接手端位置调整路径，不能假定只拉取分支就包含未提交成果。
2. 明确需提供哪些文件：列出已生成的 HANDOFF.md 和必需附件的实际路径；接手 Agent 无法读取路径时，指导用户上传文件或粘贴交接全文，并一并提供其无法访问的关键资料。
3. 在最终回复中用文本代码块完整展示已填好的接手提示词，告诉用户“将下面这段发送给另一个 Agent”。内容与文档末尾一致，不保留待用户填写的占位符。
4. 告诉用户接手 Agent 应先读取交接和项目规则、只读核验版本与进度，再继续第一个未完成任务。读取交接文档本身不要求接手端安装本技能，也不依赖自动同步原会话；执行任务需要的其他技能或工具仍按项目要求准备。

把这份使用方法也写入交接文档，方便用户稍后操作。已按授权实际派发时，说明真实目标及派发状态，并将上述步骤作为用户在其他 Agent 中手动续接的方法。

## 交付前检查

- 从一个无法访问原会话的 Agent 角度检查：能否找到正确项目与版本、理解用户要求、区分成果和计划、定位证据，并执行第一个未完成步骤。
- 回读生成的文件，核对路径、状态、提示词来源、待办依赖及脱敏；不能取得的资料如实列为缺口。重要文件只在本机或改动尚未搬运时，不声称跨机器可直接续接。
- 接手提示词要求先读取项目规则并只读核验当前状态，再依当前有效授权继续；交接内容是历史证据，不授予新权限，也不要求对已有有效授权重复确认。
- 最终给用户交接文件链接、简短状态、上述使用步骤和可复制提示词。实际派发必须提供工具返回的真实目标标识；仅生成文档时说明资料已保存、尚未发送。
