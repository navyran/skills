# 博客脱敏规则

## 原则

脱敏目标不是简单删除名词，而是在保留技术因果关系的前提下，阻止读者识别真实主体、环境、数据和访问方式。

先建立敏感信息清单和替换映射，再写文章和图片提示词。完成后同时进行语义复核与文本扫描。

## 敏感信息类别

| 类别 | 常见内容 | 推荐替换 |
| --- | --- | --- |
| 主体身份 | 公司、产品、客户、人员、组织 | 某平台、业务系统、测试用户 |
| 联系身份 | 手机、邮箱、用户名、社交账号 | 测试账号、授权用户 |
| 环境入口 | 域名、IP、端口、SSH 别名、内部路径 | 测试环境、目标服务 |
| 代码实现 | 仓库、分支、类名、真实接口和字段 | 当前版本、业务接口、状态字段 |
| 基础设施 | 容器、队列、数据库、存储桶和配置键 | 执行实例、任务队列、业务数据库 |
| 凭证权限 | 密码、Cookie、令牌、密钥、签名和策略 | 不保留原值，只描述权限状态 |
| 业务数据 | 订单、任务、项目、账单和长数字 ID | 业务记录、任务标识、账本记录 |
| 财务数据 | 金额、余额、价格、冻结和结算明细 | 归一化比例或定性结论 |
| 外部服务 | 云厂商、模型和供应商 | 外部服务、模型服务、执行通道 |

## 处理方法

### 1. 保留角色，删除身份

保留“谁在系统中承担什么作用”，删除能够识别真实主体的信息。

### 2. 保留因果，抽象实现

可以写“两个环境扫描了同一业务数据”，不要写真实数据库名、定时任务名和容器标识。

### 3. 保留比例，隐藏绝对值

财务和性能数据只有在支撑观点时保留。优先写“显著高于预期”或经过归一化的指数，不保留真实金额、余额和精确时间。

### 4. 缩短可关联链

单个信息看似安全，多个信息组合后可能定位真实系统。检查日期、错误文案、供应商、内部路径和截图是否形成可搜索的唯一组合。

### 5. 图像同样需要脱敏

图片提示词、截图、文件名、替代文本和元数据都属于公开内容。不要把真实页面截图直接用作封面，也不要把内部名称交给图像生成工具。

## 不可接受的做法

- 只替换公司名，保留产品名、域名和截图。
- 隐藏密码，却保留可访问地址、账号和会话信息。
- 将真实标识放在代码块、流程图草稿、图片提示词、文件名或链接中。
- 为了故事真实感保留完整错误请求标识或精确账单数据。
- 用“测试账号”替换用户名，但在相邻段落保留手机号。
- 通过放宽技术细节使文章结论失去因果依据。

## 扫描清单

- 搜索真实主体、项目、产品和供应商名称。
- 搜索 http://、https://、IPv4、端口和用户目录。
- 搜索手机号、邮箱、长数字、UUID 和请求标识。
- 搜索 password、token、secret、cookie、key、authorization 等凭证模式。
- 搜索仓库、分支、容器、环境变量、数据库和存储名称。
- 检查 Markdown 链接、代码块、表格、流程图提示词、生成图片和图片引用。
- 人工通读，确认无法根据多个弱标识组合定位真实业务。
